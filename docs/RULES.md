# LUMEN Operating Rules & Constraints

The LUMEN pipeline operates under strict technical and data constraints. These constraints dictate the design decisions, the features implemented, and the limitations of the current codebase.

## 1. Hardware Constraints

### 16GB RAM Limit
The pipeline was explicitly designed and mandated to run on standard hardware with a maximum of 16GB of RAM.
- **Rule**: Never load full, native-resolution image arrays into memory simultaneously.
- **Enforcement**: 
  - `generate_previews.py` uses `rasterio`'s decimated read functionality to pull out tiny thumbnails without loading the 15GB files into RAM.
  - Orthorectification and reprojection are performed block-by-block using GDAL/rasterio instead of native numpy arrays.
  - Feature matching crops out empty overlap bounds (Stage 3) before instantiating arrays in memory.

## 2. Data Limitations & Skips

### The "No-Overlap" Block
- **Rule**: The pipeline cannot magically align images that do not physically overlap on the lunar surface.
- **Current State**: The raw data provided in `data/raw/` contains OHRC images from the Lunar South Pole (lat [-85.48°, -84.66°] for calibrated NCP, and down to -89.95° for NRP) and TMC images from Equatorial/Mid-Latitude swaths (lat [-29.51°, -3.62°]). Their coordinates do not intersect.
- **Enforcement**: Cross-sensor validation (e.g., TMC-to-OHRC) is permanently blocked and out of scope until a dataset with physically overlapping geometry is provided. The pipeline logic is fully built to handle it when the data arrives.

### The Missing OHRC Geometry Skip
- **Rule**: Images missing their geometric XML/CSV sidecars cannot be orthorectified.
- **Current State**: Several uncalibrated (`_nrp_`) OHRC images from the ISSDC archive are missing their `_g_grd` GCP files.
- **Enforcement**: The `RegistrationPipeline` detects the absence of these files and raises a strict `skip_orthorectify` flag. Do not attempt to force processing on these images, as the mathematical transformation to Geographic CRS is impossible without them.

## 3. Methodological Rules

### No Mocking
- **Rule**: The dashboard and metrics must reflect 100% real outputs generated by the pipeline. No hardcoded success states or mocked API responses are allowed in the final build.

### Unbiased Validation
- **Rule**: The pipeline's accuracy must not be self-referential. 
- **Enforcement**: The final RMSE (1.932 px) reported on the dashboard is NOT the RMSE calculated during homography fitting. It is calculated by taking the finished transformation matrix and testing it against a completely fresh set of points extracted via a totally different algorithm (SIFT).
